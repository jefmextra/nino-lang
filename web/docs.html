Nino Language Reference Manual

Nino is an independent, statically typed systems programming language designed to explore formal contract verification, deterministic compiler bootstrap, and lean tooling.

Installation

Nino is distributed as a single standalone executable with no external runtime dependencies.

irm https://ninosec.me/install.ps1 | iex

On Linux and macOS systems:

curl -sSf https://ninosec.me/install.sh | sh

First Program

Create a file named app.nino. Every struct with scalar or nested fields automatically receives compile-time _to_json, _from_json, and _eq helpers, and expressions can be chained left-to-right with |>:

import "std/str.nino" struct ServiceNode { id: int, name: string, online: bool } fn main() -> int { let label = " nino_gateway_v1 " |> str_trim() |> str_to_upper() let node = ServiceNode { id: 101, name: label, online: true } print(node |> ServiceNode_to_json()) return 0 }

Run or compile your program directly with ninoc:

ninoc run app.nino ninoc build app.nino --proof -o app.exe

Variables & Mutability

Variables in Nino are immutable by default (let). Reassigning an immutable binding triggers compile-time error E0384. Mutable bindings require the explicit mut keyword and are automatically checkpointed inside software transactions.

let max_connections = 1000 mut active_workers = 0 active_workers = active_workers + 1

Control Flow, Pattern Matching, Lambdas & Pipe Operator

Nino supports structured if / else, range and collection for loops with optional step, match pattern matching, guard ... else clauses, defer scope finalizers, inline higher-order lambdas (arr_map, arr_filter, arr_reduce), and the universal expression pipe operator (|>):

let total = [1, 2, 3, 4, 5, 6] |> arr_filter(|x| x % 2 == 0) |> arr_map(|x| x * 10) |> arr_reduce(0, |acc, x| acc + x) match total { 120 => print("Pipeline verified: 120"), _ => print("Unexpected sum") }

Formal Contracts (require / ensure)

Functions support formal preconditions (require) and postconditions (ensure). These clauses are enforced at runtime and statically proven by ninoc prove and ninoc build --proof.

fn allocate_buffer(size: i64) -> i64 { require(size > 0, "Buffer size must be positive") let aligned_size = size + 16 ensure(aligned_size > size, "Alignment overflow invariant breached") return aligned_size }

Linear Ownership & Multi-Slab Arena Memory

Nino pairs garbage-collection-free execution with a thread-local multi-slab bump-pointer arena (NinoArena, chaining 4 MiB NinoArenaSlab segments), O(1) scoped marks (arena_mark() and arena_rollback(mark)), and 48-byte NinoArrHdr array headers stamped with epoch/reset-generation metadata that trap deterministically on Use-After-Rollback (CWE-416) index, push, or pop accesses. Static region analysis (E0515) rejects unpinned local allocations escaping rollback scopes unless explicitly promoted via region_pin(val), while outer arrays that grow across mark boundaries promote onto the heap and release deterministically via arr_free(arr):

let baseline = arena_used() for req_id in 0..1000 { let mark = arena_mark() let payload = "request_" + int_to_str(req_id) arena_rollback(mark) } require(arena_used() == baseline, "Zero memory leaked across 1000 cycles")

Sealed Software Buffers, Guard Pages & Zeroization

Values declared with sealed let obfuscate string literals at compile time (avoiding verbatim plaintext storage in .rodata) and use OS CSPRNG entropy (BCryptGenRandom on Windows, /dev/urandom on POSIX) to generate a per-byte nonzero XOR pad stream inside virtual-page isolated nino_sealed_t buffers locked against swap paging (VirtualAlloc/VirtualProtect PAGE_NOACCESS and VirtualLock on Windows; posix_memalign/mprotect PROT_NONE and mlock on POSIX when OS limits permit, inspectable via seal_is_locked()) with 32-bit head/tail integrity canaries. Explicit wiping uses volatile zeroing via seal_destroy(), while passing an un-unsealed sealed value or alias directly to I/O sinks (print, write_file, tcp_write) is rejected at compile time with diagnostic E0042. (This is software memory defense-in-depth, not hardware TEE/SGX encryption.)

sealed let private_key = "0x9F4B2A..." let plain = unseal(private_key) print("Access verified") seal_destroy(private_key)

Morphic Dynamic Masking & Software Transactional Memory

Variables declared with morphic mut pair XOR-masked storage with dynamic runtime keys (nino_morphic_write / nino_morphic_read) for lightweight in-process software obfuscation (not hardware memory encryption). Additionally, nested transact { ... } compensate { ... } blocks checkpoint and roll back mutated scalar variables and array slots using thread-local nino_tx_frame_t state frames if an abort or guard failure occurs:

morphic mut vault_balance = 5000 transact { vault_balance = vault_balance - 1000 guard vault_balance >= 5000 else { abort "Rollback triggered" } } compensate { print("State restored cleanly") }

Zero-Copy Foreign C Memory & Dynamic System FFI

The module std/interop.nino provides bounds-checked foreign memory borrowing (foreign_ptr_borrow, foreign_ptr_write_u8, foreign_ptr_read_u8, foreign_ptr_release), while ffi_open_system_lib, dylib_open, and dylib_sym load native OS shared libraries (msvcrt.dll, libc.so.6, sqlite3) at runtime:

import "std/interop.nino" let fptr = foreign_ptr_borrow(64, "C_ABI_X86_64") foreign_ptr_write_u8(fptr, 0, 78) foreign_ptr_release(fptr) let libc = ffi_open_system_lib("libc") let fn_strlen = dylib_sym(libc, "strlen") let n = dylib_call_c_strlen(fn_strlen, "NinoFFI")

Built-in SMT Theorem Prover & Proof-Carrying Code (PCC)

Before emitting C11 or native code under ninoc prove [--bv|--int-logic] or ninoc build --proof [--bv|--int-logic], the compiler synthesizes chronological SSA SMT-LIB2 obligations (defaulting to 64-bit BitVector QF_BV+64bit-Overflow arithmetic and signed overflow checks, IEEE 754 Float64 under QF_BVFP / QF_FP with is_nan/is_inf/is_finite/fp_abs/fp_sqrt/to_float, or unbounded Int via --int-logic, plus path-sensitive if/else guards, loop invariant proofs, and array bounds checking) and invokes Microsoft Z3. Compilations fail closed with exit code 1 if zero postconditions/invariants are present or if Z3 detects a counterexample (sat). When proven unsat, the compiler embeds the byte-array SMT spec, SHA-256 digests, an RFC 2104 HMAC-SHA256 tag (NINO_PCC_HMAC_KEY), and an RFC 8032 Ed25519 asymmetric signature (NINO_PCC_ED25519_SEED via ninoc keygen), re-verified in constant time at runtime via ./app.exe --verify-proof [--pubkey <64-hex>] [--hmac-key <k>] [--reverify-z3]:

ninoc prove examples/pcc_sound_demo.nino ninoc keygen --seed 9d61b19deffd5a60ba844af492ec2cc44449c5697b326919703bac031cae7f60 ninoc build examples/pcc_sound_demo.nino --proof -o app.exe ./app.exe --verify-proof --reverify-z3 ninoc build app.nino --strict-c11 -o app_iso.exe

Capability Matrix Sandboxing

Nino supports capability annotations on functions and scoped blocks to document and enforce execution permissions:

with capability ["read_only", "!network", "!disk"] { let calculation = 100 * 42 print("Protected calculation: ", calculation) }

Cryptographic Primitives, Ring-LWE / ML-KEM-512 & Zero-Knowledge Proofs

Nino provides built-in NIST FIPS 180-4 sha256, IETF RFC 2104 hmac_sha256 (verified against RFC 4231 test vectors) with constant-time tag comparison (_nino_ct_streq), and RFC 7519 HS256 JWT helpers (std/jwt.nino), alongside self-contained algebraic research primitives: N=64 Ring-LWE (RLWE64_*) and Category-1 Module-Lattice KEM (MLKEM512_*, k=2, N=256, q=3329 with 256-bit shared secrets via pq_generate_keypair(512) or --release-pqc), 61-bit Sophie-Germain safe-prime Schnorr signatures (pq_sign, pq_verify) backed by branchless constant-time modular arithmetic (_nino_ct_add_mod, _nino_mod_mul, _nino_mod_pow), and Pedersen commitments with 48-bit CDS OR-Sigma range proofs (zk_prove_condition, zk_verify_proof, intended for research and prototyping rather than certified production deployment):

import "std/jwt.nino" let kp = pq_generate_keypair(768) let sig = pq_sign("LEDGER_TX_01", kp["private_key"]) require(pq_verify("LEDGER_TX_01", sig, kp["public_key"]), "Valid signature") let token = jwt_sign_hs256("{"sub":"node_1"}", "secret_key") require(jwt_verify_hs256(token, "secret_key"), "Valid JWT HS256")

Threshold Multi-Party Computation (MPC)

The module std/mpc.nino implements dynamic degree-(k-1) Shamir Secret Sharing over the 61-bit Mersenne prime field 2305843009213693951 (M61) with overflow-safe modular arithmetic, CM elliptic-curve Feldman Verifiable Secret Sharing (VSS) commitments over curve order M61 (mpc_verify_share_vss), duplicate/tampered share rejection, Lagrange polynomial interpolation, and OS CSPRNG coefficient sampling.

import "std/mpc.nino" fn main() { let key = mpc_split_secret(1337, 3, 5) mut quorum = [] quorum = push(quorum, key.shares[0]) quorum = push(quorum, key.shares[1]) quorum = push(quorum, key.shares[2]) let reconstructed = mpc_reconstruct_secret(quorum, 3) print("Reconstructed secret: ", reconstructed) }

Static Safety Linter (Control-Flow & Complexity Checks)

The command ninoc lint [--strict] <file.nino> performs exploratory static checks inspired by MISRA-C:2012 and JPL Power-of-10 guidelines, verifying delimiter balance (MISRA-1), acyclic call graphs without direct recursion in strict mode (JPL-1), absence of unbounded while true loops (JPL-2), and function length bounds (JPL-4). For ISO C11 backend strictness, pair with ninoc build --strict-c11 (-std=c11 -pedantic-errors):

ninoc lint --strict examples/pcc_sound_demo.nino

Universal Mobile Engine (Android JNI & iOS Swift) & Shared Libraries

Nino compiles directly into native shared libraries (.dll, .so, .dylib) via ninoc build --shared and automatically generates mobile bindings via ninoc mobile:

ninoc build vault.nino --shared --proof -o vault.dll ninoc mobile vault.nino --pkg com.nino.vault --class VaultBridge -o build/mob
  • Android NDK: Emits JNI C11 glue (_jni.c), compiles the native shared library, and generates a Kotlin wrapper class (VaultBridge.kt) with external fun bindings.
  • iOS / macOS: Emits a C11 bridging header (.h), Clang module.modulemap, and a Swift 5 wrapper struct (VaultBridge.swift).
  • Runtime Dynamic Linker API: Native builtins dylib_open, dylib_sym, dylib_call_i64, dylib_call_str, and dylib_close provide direct OS dynamic loading (LoadLibraryA / dlopen).

Z3 Counterexample Witness Synthesizer, Equivalence Prover & Flight Recorder

When a formal contract is violated (sat), ninoc witness extracts the concrete counterexample model from Microsoft Z3 and generates a standalone executable .nino test file that deterministically reproduces the failure at runtime. ninoc equiv <v1.nino> <v2.nino> proves whether two refactored functions are mathematically identical across all 64-bit inputs:

ninoc witness examples/pcc_fail_demo.nino -o repro_witness.nino ninoc equiv v1_fee.nino v2_fee.nino ninoc trace pilots/ledger_microservice.nino

The runtime also includes a 256-slot thread-local ring buffer (trace_record, trace_checkpoint, trace_chain_hash, trace_dump) that hashes every state transition into a rolling FIPS 180-4 SHA-256 chain.

Native C-Header Bindgen, Canonical Formatter & CycloneDX SBOM

ninoc bindgen parses C header files (#define constants, struct definitions, and function prototypes) directly into Nino extern fn FFI bindings without requiring external libclang installations. ninoc fmt formats Nino source code into canonical 4-space block indentation, and ninoc sbom generates a cryptographic CycloneDX v1.5 JSON Software Bill of Materials:

ninoc bindgen include/telemetry_abi.h -o src/telemetry_ffi.nino ninoc fmt src/main.nino --check ninoc sbom pilots/ledger_microservice.nino -o ledger.sbom.json

High-Density Primitives, Multi-Core Threading, Industrial Pilots & Standard Library (31 Modules)

In addition to systems and cryptographic modules, Nino includes practical standard library modules and multi-core runtime primitives:

  • std/json.nino: Zero-allocation JSON parser, string escaper, and object builder (json_get_string, json_get_number, json_get_bool, json_object2, json_object3).
  • std/http.nino: Native socket HTTP/1.1 client and REST response builder (http_get, http_post_json, http_build_json_response).
  • std/fs.nino: Cross-platform filesystem I/O and path utilities (fs_read_text, fs_write_text, path_join, path_basename, path_dirname, path_ext).
  • std/str.nino: String manipulation utilities (str_contains, str_trim, str_replace, str_to_upper, str_to_lower, str_pad_left).
  • std/uuid.nino: Hardware CSPRNG UUID v4 generator (uuid_v4) plus Base64 and Hex encoders/decoders (base64_encode, hex_encode, hex_decode).
  • std/env.nino: Dotenv (.env) configuration file parser and environment loader (dotenv_get_from_file).
  • std/regex.nino: Regular expression matcher supporting anchors, wildcards, quantifiers, and character classes (regex_match, regex_search).
  • std/csv.nino: RFC 4180 CSV parser and serializer (csv_row_count, csv_get_cell, csv_build_row3).
  • std/jwt.nino: RFC 7519 JWT (HS256) token signer and verifier backed by RFC 2104 hmac_sha256.
  • Compile-Time Struct Synthesis & Expression Pipe: Automatic scalar and nested <Struct>_to_json, <Struct>_from_json, and <Struct>_eq generation, plus expression-level |> chaining, db_query_json, str_split, str_join, and arr_sort.
  • Higher-Order Inline Lambdas & Native OS Threading: Zero-overhead arr_map(|x| ...), arr_filter(|x| ...), and arr_reduce(init, |acc, x| ...), plus native multi-core OS threads (thread_spawn, thread_join, cpu_core_count) and dynamic system library FFI (ffi_open_system_lib).
  • Industrial Reference Pilots (pilots/): Reference implementations for FinTech HTTP/1.1 microservices (pilots/ledger_microservice.nino), Industrial IoT Edge gateways (pilots/iot_edge_telemetry.nino), and RFC 9669 64-bit eBPF/XDP packet firewalls (pilots/xdp_packet_firewall.nino).

Self-Hosting & Bootstrap Pipeline

Nino features a modular self-hosted native compiler (12 modules under compiler/ with compiler/ninoc.nino as entrypoint) supporting standard // and /* ... */ comments, parsing Nino source code, verifying invariants with Z3, and emitting freestanding ISO C11 (--backend=gcc / --backend=llvm) or direct PE32+/ELF64 machine code (--backend=native*, ninoc asm) into standalone executables (ninoc.exe).

Reproducible Bootstrap Pipeline

To verify compiler reproducibility and deterministic output, Nino enforces a three-stage fixed-point bootstrap check in CI:

Stage Description
Stage 1 Initial native binary compiled from bootstrap/ninoc_seed.c (stage1.exe).
Stage 2 The Stage 1 binary compiles compiler/ninoc.nino into stage2.exe.
Stage 3 Stage 2 recompiles compiler/ninoc.nino into stage3.exe. Checksums are verified bit-for-bit: SHA-256(Stage 2) == SHA-256(Stage 3).

Micro-VM & Bare-Metal Kernel Target

Nino can target freestanding bare-metal x86 environments (boot/build_kernel.nino and examples/kernel_os.nino) with Multiboot headers and direct VGA/UART hardware output for QEMU micro-VMs:

ninoc run boot/build_kernel.nino

Database Wire Drivers & One-Call SQL-to-JSON

The standard library module std/db.nino and runtime provide native PostgreSQL v3 TCP wire, hybrid SQLite, and Redis drivers with runtime introspection via db_driver_mode(): db_postgres_connect speaks PostgreSQL v3 wire frames over TCP (native:postgres-wire, StartupMessage, Cleartext/MD5 auth, Query/DataRow/ReadyForQuery) and fails closed ("" / -1 / "disconnected") when offline; db_sqlite_open dynamically resolves host sqlite3 via LoadLibraryA/dlopen (native:sqlite3) when present or falls back transparently to a dynamically resizable in-memory SQL subset (embedded:sqlite-mem); db_redis_connect performs a 50ms non-blocking RESP-2 TCP probe (native:redis-tcp) with an in-process dict fallback (embedded:redis-mem):

let db = db_sqlite_open(":memory:") print(db_driver_mode(db)) db_sqlite_exec(db, "CREATE TABLE accounts (id INTEGER, owner TEXT, balance REAL)") db_sqlite_exec(db, "INSERT INTO accounts VALUES (101, 'Alice', 2500.0)") let json_rows = db_query_json(db, "SELECT id, owner, balance FROM accounts WHERE balance > 1000.0") print(json_rows)

Dynamic Actor Mailboxes, Supervisors & Async Channels

The modules std/actor.nino and std/channel.nino provide mutex-synchronized dynamically scaling actor registries and resizable circular inbox queues (spawn_actor, actor_send, actor_receive, actor_inbox_len), atomic behavior patching (actor_patch), cooperative fault-recovery dispatch (spawn_supervisor, supervisor_dispatch), and FIFO channels (channel_create, channel_send, channel_recv) alongside native OS threads (thread_spawn):

let pid = spawn_actor("OrderEngineV1") actor_send(pid, "TX_101") print(actor_receive(pid)) actor_patch(pid, "OrderEngineV2")

Distributed Raft Consensus & P2P Gossip Mesh

The modules std/consensus.nino and std/mesh.nino implement quorum leader election, replicated log commitment (raft_create_cluster, raft_elect_leader, raft_propose_entry), and PQC-authenticated peer-to-peer gossip broadcasting (mesh_node_init, mesh_broadcast, mesh_receive):

import "std/consensus.nino" let nodes = ["node_a", "node_b", "node_c"] mut cluster = raft_create_cluster(nodes, 2) let elected = raft_elect_leader(cluster, "node_a", 1) let committed = raft_propose_entry(cluster, "EPOCH_01_COMMIT")
